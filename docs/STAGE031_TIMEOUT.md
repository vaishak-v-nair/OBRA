The previous implementation gave the same configured90-second value to HttpOptions, HTTPX and asyncio. SDK `_api_client.py` converts the HttpOptions milliseconds to seconds, sets `X-Server-Timeout=ceil(timeout)` unless supplied, and applies the same value to the HTTPX request. Thus the caller supplied a server deadline too. The evidence does not establish an independent provider outage, quota cause or exact elapsed duration. Historical per-phase timing was absent: **90 seconds was configuration, not a measurement**.

The server budget remains T (`ORBA_PM_TIMEOUT_SECONDS`, owner configuration90). The adapter now supplies X-Server-Timeout=T, SDK/HTTPX transport=T+5 (95), and outer asyncio=T+10 (100). Existing lease=T+45 (135), startup60, absolute publication285, proxy290 and client300 remain bounded. This separates equal-deadline races; it does not guarantee the provider can finish within T or prove an upstream incident was fixed. No automatic retry or continuation was added.

Safe monotonic diagnostics record admission, running confirmation, provider, validation and graph-flush durations. Stored JSON explicitly names `before_terminal_commit`; complete persistence acknowledgement is logged only after commit. Error origins distinguish upstream HTTP, transport timeout, local envelope timeout, transport unavailability and labeled deterministic doubles. Logs contain safe run UUID/stage/duration/category/status/attempt/state fields, never briefs, keys, headers, cookies or provider bodies. An expired-lease detection log describes a proposed state; only committed records establish the final state.

The Next route distinguishes its deadline/client disconnect/API transport failure from provider errors and reports an unknown result when dispatch may have happened. Cancellation may stop the proxy fetch without stopping already dispatched synchronous API/provider work. A browser failure therefore retains the account/project-scoped request UUID and uses GET recovery, without another POST. A confirmed failed/interrupted own run is re-read before an explicit new-UUID Retry; each new run records one provider attempt. An authoritative pre-admission rejection or CSRF preparation failure permits a later explicit submission without inventing a failed run. Approved plans remain immutable. Input snapshots can be restored explicitly through the authorized API; browser storage never holds briefs or credentials.
