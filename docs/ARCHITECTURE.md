The scope remains local development; passing tests do not certify production security. Current verified and blocked scope is in VERIFICATION.md.

## Data and migration

Users have UUID, normalized unique email, salted Argon2id password hash, display name, status and aware timestamps. Sessions have UUID, user FK, unique token hash, created/expiration/revocation timestamps. Workspaces have UUID, name, unique readable slug with random suffix, creator FK, timestamps and a restricted-legacy flag. Memberships have unique workspace/user pairs, checked roles and joined timestamp. Invitations have unique token hashes, partial unique pending workspace/email index, checked role/status, inviter/email/expiry and terminal timestamps. Appropriate FK, membership/session/project lookup indexes are in the migration. SQLAlchemy models match Alembic (`alembic check`).

Projects retain UUID/title/description/created status/timestamps and gain a nonnull workspace FK plus nullable creator FK. New projects always use the validated session's user and an authorized supplied workspace. Existing rows are backfilled into the fixed restricted workspace `00000000-0000-0000-0000-000000000001`, with creator null and no members. No default signup membership is created there. The migration adds the workspace column nullable, inserts/backfills ownership, then enforces not-null; original values are untouched. Repeat upgrade is a no-op through the Alembic revision record. Before the ownership upgrade, a native loopback listener probe rejects a running local API at port 8000 (ORBA_API_PORT selects a custom port). The known isolated orba_test database/role is exempt; no application authentication check is bypassed. Operators must independently stop remote/custom deployments. Downgrade deliberately fails instead of re-exposing private data or dropping auth state.

The terminal-only claim command requires explicit target workspace, existing Owner and selected project UUIDs. It checks all rows under lock before making any transfer. Default is dry run; --apply changes only ownership/creator, preserving original updated_at explicitly. It refuses already-claimed rows. Local operator/database access is its authority; no HTTP claim route exists.

## Authentication, cookies and CSRF

FastAPI validates every protected request against a stored SHA-256 hash of a 32-byte random opaque token, unrevoked/unexpired session and active User. Login/register revokes the presented valid old session and creates a new one. Logout persists revocation and expires the cookie. The UI clears local protected state on every logout attempt and distinguishes an unconfirmed server revocation after network failure. Password verification uses maintained argon2-cffi Argon2id with unique salts; unknown users receive comparable dummy hash work. Passwords are not trimmed or Unicode-normalized. User response schemas omit hashes/tokens. NewPassword is a reusable Pydantic annotated type with15-128-code-point bounds and the existing whitespace-only guard. RegisterInput uses it; LoginInput remains1-128 and does not apply the new-credential minimum during verification or eligible hash upgrades. OpenAPI exposes both contracts. Future change/reset schemas must reuse NewPassword, but those workflows are not implemented. The policy rollout performs no migration, hash rewrite, forced reset or session invalidation. The form counts code points before locking/submitting, removes native UTF-16 maxlength clipping in both modes, retains autocomplete/pasting, and associates invalid-field help/errors without storing credentials.

Cookie: host-only, Path=/, HttpOnly, SameSite=Lax, explicit max-age. COOKIE_SECURE is configurable for local HTTP and required true when WEB_ORIGIN is HTTPS. Session lifetime is bounded and enforced server-side. Session cookie names and lifetimes are API configuration, not frontend claims.

GET /auth/csrf returns a token derived by HMAC from the currently validated opaque session credential; it is not stored in browser persistence. The client sends it on every POST/PUT/PATCH/DELETE. Before authentication, the endpoint creates a random HttpOnly SameSite=Strict cookie and returns its matching token. The exact configured Origin is independently required on all writes, including login/register, and no cross-origin read permission is granted. Tokens are compared as bytes so malformed non-ASCII headers produce 403 rather than TypeError. Responses are no-store. Invitation links use fragments and the root page declares no-referrer.

The same-origin Next handler forwards only required headers and preserves multiple Set-Cookie values. It does not trust browser-supplied forwarded IP headers and does not create a competing session. API_URL is server-only and read at request time. Upstream failure produces a truthful 503. The frontend never automatically retries a write; unknown outcomes retain drafts and warn about possible duplicates.

## Brute-force limits and concurrency

PostgreSQL stores attempt timestamps under SHA-256 account and peer-IP keys. Each request locks both bucket keys in sorted order using transaction advisory locks, checks a rolling window, persists attempts and commits before password verification. Failed and successful attempts count. Defaults: 5 per account / 15 minutes, 100 per shared peer IP / 15 minutes. Expired attempt rows are removed on future attempts. Uvicorn must run --no-proxy-headers; otherwise its loopback proxy defaults can trust forged X-Forwarded-For values. The Next proxy strips those headers regardless. This local limiter has shared-IP lockout/throughput limitations and is not a full internet abuse-control system.

All membership mutations, invitations and project writes first lock the workspace row, then read the caller's current role. Invitation acceptance locks workspace before invitation, refreshes the invite under lock, verifies pending/unexpired/email match, rechecks inviter privilege and inserts the unique membership and consumed state in one transaction. Consistent lock order prevents the obvious invite/role deadlock. Concurrent owner demotions preserve one Owner; concurrent accepts produce one membership. Reads use current membership joins. No frontend role control substitutes for backend enforcement.

## Roles and API contracts

Owner: read/write/invite/manage roles; cannot demote/remove final Owner. Admin: read/write, invite and manage only Member/Viewer; cannot promote self, affect Admin/Owner or issue Owner/Admin invitations. Member: read/write projects. Viewer: read only. Only an Owner can promote an existing member to Owner. Invitation creation never grants Owner.

Existing routes are retained: POST/GET /api/v1/projects and GET /api/v1/projects/{id}. Create and list now require workspace_id; create forbids creator_id/status injection. PATCH /projects/{id} edits bounded title/description after write-role enforcement. List remains newest-first with deterministic UUID tie-break and 50-row UI pagination. Unauthorized resources use the same 404 response as absent ones. Expected validation, unauthenticated, forbidden, missing, duplicate, throttled and DB failures use structured 422/401/403/404/409/429/503 envelopes. Readiness checks the new tables/columns, not only network connectivity. Liveness remains DB-independent.

Auth routes: register/login/logout/me/csrf. Workspace routes: create/list/detail/members, invitation create/list/revoke, role PATCH, membership DELETE. Invitation acceptance requires authentication and CSRF; no unauthenticated resource preview exposes workspace data. The invitation link is returned only from authorized creation and never reconstructed by listing. Expired is a derived read status; accepted/revoked timestamps and statuses are persisted. No email is sent.

## Frontend state and preserved design

Existing semantic palette, Button, navigation, ProjectForm, project list/detail, theme and responsive layouts are retained. Added auth forms, account menu, native workspace selector, creation page, member/invite settings and acceptance page. AuthGate blocks protected children while session checks are pending and clears component state on account/workspace/route changes. Request generations prevent stale session refresh responses overwriting newer identity. A workspace ID in sessionStorage is only a preference and is matched against authorized server workspaces. No password, session token or invitation token is stored there. CSRF tokens live per request; invitation fragments stay in URL/in-memory flow until consumed.

Mobile navigation includes native select/summary controls in its visibility-aware focus trap and restores focus on Escape. Destructive membership/role actions use confirmations and only update server state on real success. Viewer project creation and editing controls reflect the returned role, with backend checks independently enforcing it. Permission revocation is enforced on subsequent requests; no real-time push is claimed.

## Product Manager contract and persistence

`pm_schemas.ProductDocument` is the sole authoritative output/edit contract. Pydantic forbids unknown fields and wrong scalar types. It bounds all text/collections and validates stable unique node keys, story format, nonempty Given/When/Then criteria, valid requirement/dependency references and an acyclic story dependency graph. Limits are eight epics, forty stories, 160 criteria, 80,000 document characters / 512 KiB. Root overview/scope/uncertainty nodes live once in `ProductPlan.content` JSONB; epics, stories and criteria live in relational tables and are assembled with three ordered bounded queries. The API does not persist a second full-PRD JSON copy. Stable child UUIDs are retained on unchanged keys across edits.

Each attributed node records brief/title/description/context/suggested/assumption/human provenance. Provider-supplied quotes must be literal substrings of the selected input; source claims of human authority are rejected. Context stores exact version/revision/hash and bounded source-node snapshots, including transitive origin and blocker dispositions. The server carries unresolved blocking confirmations forward even if a later model omits them. Editing compares semantic content and parent keys, disregards client provenance and records the actual session actor for changed nodes. Blocking original wording cannot be erased or downgraded; human resolve/defer needs a reason and recorded actor/time. Textual matching does not establish semantic entailment or business truth; approval requires human review.

`ProductManagerRun` stores actual initiating user/session, workspace/project, executor fencing UUID, client request UUID, versioned canonical request/snapshot hashes, immutable input snapshot, provider/requested model, prompt version/hash, start/deadline/completion times, returned identifiers/usage and safe error/diagnostic references. Internal diagnostics retain exception type, validation locations and allowlisted provider status/request ID/Retry-After, not raw bodies/headers/stack traces or credentials. Raw reasoning text is neither persisted nor exposed. No dollar estimate is fabricated.

`ProductPlan` has monotonically increasing per-project version, optimistic revision, draft/approved/superseded state, root content hash, generating run or human-copy source, editor and approval evidence. Same-project composite FKs bind runs, sources and child ownership; unique constraints prevent duplicate request/copy IDs and duplicate version/run results. A partial unique index permits one current approval/project and another one active run/project. Workspace locks serialize version allocation, edits and approvals. The Stage03 migration is additive, forward-only and never rewrites existing project/auth records. Migration probes seed populated Stage01/02 schemas in the guarded test DB and compare original values exactly after real upgrades.

Plan detail holds a shared lock on its root while assembling the relational graph, keeping root revision/hash and children coherent during a concurrent save. Run reads similarly hold shared locks while joining resulting plan references. A forced real PostgreSQL reader/writer schedule verifies that an editor waits, the first read returns its original coherent revision, and the next read returns the saved revision.

### Stage03.3 configuration and request identity

`pm_models_policy` holds three reviewed stable Gemini identifiers and model-specific thinking support. It is a small policy table, not a router or Model Hub. Settings, read-only readiness and adapter share it. LOW is the default;3.8 rejects minimal, while3.6/3.5 Flash-Lite permit it. Missing provider remains a setup state; invalid configured values fail closed, including at startup, with input-hidden validation diagnostics. The runtime model stays explicit and historical requested/returned model strings are not revalidated against today's list.

The new content bound sums UTF8(prompt), UTF8(canonical provider hint) and UTF8(canonical authorized snapshot). Default48000bytes, configurable8192-96000. It supplements existing character/context/body bounds and accepts equality. For a new UUID it runs after membership/session/replay checks and before insertion/dispatch. Raw request hashing rejects invalid Unicode without exposing it. Exact replay returns the original run despite current lower caps/model/prompt changes; different payload with the same UUID still conflicts. The adapter independently checks copied settings and the same size formula before creating a client. Counts/hint hash/thinking/output/input limits are stored as the run's original safe generation_configuration and retained when terminal timing/error diagnostics merge.

Gate B's profile additionally binds thinking, content cap and provider-hint hash, separately from authoritative-schema hash. Readiness checks the exact chosen model's capability URL and limits; C/nested preflight validate stored artifacts without a request. No schema migration, credential change, history rewrite, live latency improvement or provider-availability fix follows from these changes. See [the dated investigation](STAGE033_PROVIDER_RELIABILITY.md) and [test plan](STAGE033_TEST_PLAN.md).

```text
Authenticate + Origin/CSRF + body/input validation
  capture scalar actor/session UUIDs; CLOSE the dependency DB session
  reserve pending (global advisory admission -> workspace -> project -> session locks; COMMIT)
  pending -> running (recheck original authority/executor/deadline; COMMIT confirmed)
  RELEASE all DB connections -> ONE bounded provider request
  validate actual JSON / graph / provenance / context blockers
  workspace -> project -> run -> original session locks, fresh authority + deadline
  persist entire graph + actual metadata -> recheck clock/session -> succeeded (ONE COMMIT)
  response uses a fresh persisted read
```

Provider/schema errors persist failed status and no plan. Expired leases become interrupted; their actual provider failure cause can remain recorded separately. Terminal success is never replaced by a late failure. A final commit acknowledgement can be lost after success: the service reconciles by fresh read and otherwise returns `run_outcome_unknown`, never blindly retries execution or labels it failed. Exact idempotency-key/payload replay returns its persisted run; mismatched input is 409. Replay never resumes pending/interrupted work. Global local defaults are two active requests, one/project and five attempts/user/twenty globally per hour (including failed/missing-config attempts). Admission uses PostgreSQL locks, not an in-memory/distributed claim.

Each DB phase uses pool timeout 2s, connection timeout 3s, lock timeout 1s, statement timeout 2s and transaction timeout 10s (PostgreSQL18). Pending lease is 20s; running lease is provider timeout +45s; startup dispatch budget is 60s and overall publication fence 285s. PM POST/PUT bodies have a five-second streamed-read deadline and 256/512 KiB limits before JSON parsing. The proxy preserves ordinary 15s upstream behavior and permits 290s only for generation POST; the browser generation bound is 300s and caller AbortSignals are retained. A client disconnect can leave its bounded synchronous server thread running, so usage may still occur. This is best effort continuation, not cancellation, resume, a job queue or an exactly-once billing guarantee.

On startup and every five seconds a bounded sweep locks at most 100 expired runs with SKIP LOCKED and marks them interrupted. Project run GET/admission also reconciles expired leases. No provider request is recovered/replayed. Database outages are reported and reconciliation retries its read/update on the next sweep; no imaginary recovery work is displayed.

## PM APIs, authorization and UI

All routes below are under `/api/v1/projects/{project_id}` and require current project/workspace membership. Cross-workspace IDs return private 404, including run diagnostics. Writes also require Origin/CSRF and the original active session. Viewers read; Member/Admin/Owner generate/edit/copy drafts; only Owner/Admin approve. Publication checks current authority twice (including after graph flush) using fresh database time and the initiating session. Logout/role changes serialize against finalization via locks; if authority changes first, no plan commits. Once a valid publication commits, a later logout does not retroactively erase it.
