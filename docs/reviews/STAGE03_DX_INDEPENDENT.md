## Ranked gaps and fixes

1. **P0 — Make the verification interface executable and truthful.** Define proposed root commands and modes now, rather than leaving “extend verify.ps1” as an implementation detail. Recommend Full as the default mandatory mode, with a separately named Core mode that reports core-only/PARTIAL evidence. Missing credentials must make Full exit nonzero with BLOCKED; core checks should still produce their actual results. Keep live API and live browser calls separately identified, explicitly invoked, bounded and sequential. Neither may reuse a canned plan. Distinguish provider doubles, real PostgreSQL integration, actual SDK failure tests and actual successful provider execution in the report. Do not count the intentional exit-1 experiment as a passing test. Record nonsecret command identities, outcomes, counts and blockers.

2. **P0 — Specify the transport recovery contract before implementing UI.** `api.ts:20–30` currently overwrites the caller's abort signal, imposes 20 seconds and discards structured error metadata. Define a typed error carrying category, status, field paths, run/diagnostic references and Retry-After, plus operation-specific unknown-outcome states. Give only PM generation a deadline exceeding the provider deadline plus finalization allowance. Preserve caller cancellation semantics and document that browser cancellation does not establish provider cancellation. Test CSRF-fetch failure, lost generation response, failed status GET, stale save and uncertain approval without automatic write retries.

3. **P1 — Put Stage 03 onboarding at the README front door.** Add exact server-only variable names, accepted bounds, where local configuration belongs, and separate “configured” from “provider executed.” Explain that ChatGPT/Codex sign-in supplies no runtime key, and identify credential/model access as a mandatory live-verification dependency. Provide safe authenticated API examples showing Origin/CSRF without exposing real tokens. Link the schema, lifecycle/error reference, upgrade guide and verification report. Replace the obsolete stage prohibition only with the owner's actual authority.

4. **P1 — Close the cleanup and upgrade evidence gap.** `prepare_tests.py:19` checks database and role, while README claims cleanup is restricted to port 54330. Validate loopback host and expected test port too; test rejection before any migration/truncation. Explicitly enumerate new PM child tables in guarded cleanup. Preserve the contract's populated Stage 02-to-03/repeated-upgrade/drift tests and compare original fields, identities, memberships and timestamps. Document a concrete offline backup/restore procedure without introducing reset or downgrade shortcuts.

5. **P1 — Measure setup and narrow compatibility claims.** Publish cold and warm setup measurements separately, stating hardware, prerequisite/cache state, tested tool versions and start/end events. Measure first persisted project separately from first real generated plan, including configuration/provisioning prerequisites. Record failures and manual steps. Choose a reproducible tested runtime baseline; wider Node/Python ranges need actual matrix evidence or an explicit unverified label. No five-minute estimate is justified by this static review.

6. **P2 — Resolve owner taste choices explicitly.** Prefer one root verification entry point, one official provider adapter and no production fake-provider switch. Retain the proposed local admission limits as visible, documented defaults pending owner decision C04. Include the human-copy draft operation C05: it gives correction/history a clear path without another paid generation. Keep approved-versus-draft and saved-versus-unsaved state explicit; do not substitute a richer dashboard for these distinctions.
