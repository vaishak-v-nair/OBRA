## Concrete refinements before the paid handoff

1. **P1 — Make the readiness result unambiguous and safe.** Keep all nine planned statuses: `not_configured`, `invalid_configuration`, `model_not_supported`, `credential_error`, `provider_unavailable`, `rate_limited`, `timeout`, `ready_for_attempt`, `unknown`. Define the decisive positive metadata fields and exact canonical requested/returned model comparison. An absent action/name/limit is unknown; an explicit incompatible action is unsupported. Do not infer capability, remaining quota or access from model-name syntax. Catch Settings validation using allowlisted field/category messages; do not stringify its ValidationError, error inputs, environment, key, provider body or arbitrary exception text. State the separate metadata10s HTTP/server and12s outer bounds alongside the effective generation server/transport/envelope/output/admission limits.

2. **P1 — Dispatch the metadata GET exactly once in B.** The current root runner calls `require_live_opt_in`, and `playwright.live.config.ts:3` invokes `live-preflight` again. If readiness is put in `require_live_opt_in`, `execution_profile` or that low-level preflight, a single B can cause duplicate metadata requests. Keep the network operation in the single B orchestration path after opt-in, current-A, profile and cheap local port/lock validation. Reuse its artifact; subordinate entrypoints can validate proof/prerequisites without refetching. Missing/stale A, missing opt-in/config, occupied test ports and held gate lock must dispatch zero provider requests. Low-level commands must retain their existing paid guards and cannot independently certify B.

3. **P1 — Validate the new evidence content.** Hashing `model-readiness.json` is necessary but not sufficient. Require its successful typed status, false generation-verification flag, exact model/current nonsecret profile, source identity, parent A/attempt linkage, check timestamp inside this attempt and one recorded metadata request before browser dispatch. Make it a required artifact in both B production and Gate C validation. Missing, altered, incomplete, stale, non-ready or controlled readiness cannot certify current B. A ready artifact without a genuine successful generation/SQL/browser flow still leaves Stage03 PARTIAL.

4. **P1 — Enforce the one-generation ceiling before dispatch.** The existing live scenario counts page requests after they occur (`tests-live/pm-live.spec.ts:10-11`); a final count assertion cannot stop a second paid POST. Use the planned narrowly scoped test-only transport guard to pass the first generation request through to the real services and abort any second before dispatch. Record attempted, allowed and aborted counts clearly; an aborted duplicate fails the flow, never counts as an actual second generation. The guard must not fabricate model/API responses, intercept auth, or weaken the same-plan SQL/edit/approval/isolation assertions. No retry can be triggered to repair B.

5. **P2 — Put the safe next action where the operator sees it.** Add the command/exit distinction to README’s Product Manager setup and link the current Stage03.2 test/verification contract from Verification. Missing config points to server-side setup and known precedence; bad credentials point to checking local access without automatic rotation; explicit unsupported metadata points to reviewing the configured identifier without switching it. `unknown` says which safe field/category is absent and that generation remains unverified. Rate limiting/unavailability/timeouts say no generation was dispatched by this check and do not instruct an immediate paid retry. A stale A message names `pwsh -NoProfile -File scripts/verify.ps1` as the safe repair. All output remains safe to share without `--verbose` environment dumps.
