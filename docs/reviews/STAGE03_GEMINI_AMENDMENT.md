Ranked remaining risks:

1. **HIGH — Session expiry can occur during publication writes.** `pm_service.py:410` checks the original session before `create_plan`; lines 424-433 check only the run deadline after inserting the graph. `check_session:68-81` correctly serializes logout/revocation with row locks, but time-based expiry can advance while those locks remain held. **Fix:** after all graph flushes, recheck the original session's expiry against a fresh database clock and define that final authority fence as the publication decision. Retain the same locked session/user/workspace through commit; do not reauthorize using a replacement login session. Add a controlled expiry-during-finalization case alongside both logout ordering schedules. **Confidence:** high from control flow; no race executed. **Tradeoff:** a paid, valid response can be rejected when its initiating session expires.

2. **HIGH — Selected-context blockers can disappear in regeneration.** `_snapshot` preserves confirmation disposition/reason but omits `blocking` and `active` (`pm_service.py:135-143`). `validate_generated` propagates an individual quoted node's origin, yet only checks confirmations that the new response includes (`pm_schemas.py:180-210`). It does not require unresolved blocking items from selected context to survive; the new document permits an empty confirmation list. **Fix:** snapshot blocker identity, active/blocking flags and human disposition evidence, then enforce server-owned lineage for inherited unresolved blockers. The model may propose new text but cannot erase the obligation or confer a human resolution. Test an assumption/blocker carried through two context generations and omitted by the second response. **Confidence:** high, static data-flow gap. **Tradeoff:** conservative inherited blockers require explicit human disposition even when a model proposes narrower scope.

3. **MEDIUM — Provider failures discard useful safe metadata and blur their phase.** `pm_provider.py:153-188` retains HTTP code and exception type, but drops available allowlisted provider status/request ID and bounded Retry-After. Its broad `ValueError` category also covers SDK decoding/response validation failures after dispatch, not just invalid local configuration. Success/refusal metadata is captured separately at lines 191-238, which is sound. **Fix:** preserve sanitized enum-like provider status, header request ID and capped numeric Retry-After without response bodies/messages. Distinguish pre-dispatch configuration rejection from malformed provider/SDK response where observable; otherwise state the phase is unknown. Do not manufacture usage. **Confidence:** high for metadata omission; medium for exact SDK exception paths pending isolated checks. **Tradeoff:** a small allowlist loses arbitrary provider detail while preserving actionable evidence safely.

4. **MEDIUM — Late failure status is not deadline-fenced.** `record_failure:290-292` changes any active run to its supplied status without checking the persisted deadline. After a process pause, a provider error can mark an already-expired lease `failed` if the reconciler has not yet marked it `interrupted`. Terminal success remains protected. **Fix:** under the run lock, use a fresh database time and select interrupted status for expired leases, preserving the actual provider cause/metadata separately. Retain immutable terminal states and explicit unknown persistence on write failure. **Confidence:** high, unexecuted scheduling case. **Tradeoff:** execution status and provider failure cause need distinct meanings in the UI/evidence.

5. **MEDIUM — Live and integration proof remains an explicit delivery gate.** The amendment records catalog HTTP200 and pending model selection, neither generation evidence. `generate(..., provider=None)` permits isolated unit injection (`pm_service.py:302`); such results must never become live-run evidence. **Fix:** independently run actual configured Gemini API generation and actual browser Generate→edit→reload→exact approval→reload, with sanitized real model/response/usage evidence and unrelated-user UUID denial. At router integration, snapshot actor/session IDs and explicitly release the authentication transaction before invoking this service; the service's own short sessions do not prove caller release. Verify populated migration preservation, malformed-output negatives, unknown commits and lease/permission races separately. **Confidence:** high that source alone cannot establish these outcomes. **Tradeoff:** live verification requires selected-model access and bounded paid calls; missing prerequisites remain BLOCKED for live scope.
