## Required acceptance refinements

1. **Publish and test the two distinct contracts.** Add generated OpenAPI assertions for `RegisterInput.password` minLength15/maxLength128 and `LoginInput.password` minLength1/maxLength128. Verify a future consumer can reuse `NewPassword` without changing login. Registration rejection tests must check both users and sessions remain unchanged, and error bodies must not echo password input.
2. **Make legacy preservation testable without an auth bypass.** Use a real Argon2id hash and real persisted session for an explicitly labeled 12-character legacy account in guarded `orba_test`. Verify `/auth/me` before and after the policy-compatible login, distinguish the independently preserved session from the deliberately rotated presented session, and retain existing eligible-rehash behavior. No development account seeding, migration, forced reset or fixture through the newly restricted registration endpoint.
3. **Keep every mandatory identity, then append coverage.** Static baseline inventory currently contains 102 `backend`, 139 `stage031_backend`, 51 `core_browser`, and 18 `controlled_browser` entries; these are file-entry counts, not newly executed results. Gate A selects `stage031_backend` when present, so adding only to `backend` would not make new backend identities mandatory. Preserve every existing entry in all four arrays and add new cases to the active baseline plus each applicable browser project. Do not weaken report checks or accept skips/retries/flaky outcomes.
4. **Keep evidence claims scoped.** Record the actual new Gate A commands, exits and structured counts in `docs/VERIFICATION.md`. Recompute Gate C against the new source without editing old receipts or erasing the upstream503 failure. A password-policy regression pass cannot supply new live-model evidence or authorize the next paid attempt.
